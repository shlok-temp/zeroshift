# Zeroshift

Paste a `docker-compose.yml`, get the two YAML files Zerops needs — plus an
honest list of everything in your compose file that will not survive the move.

Built for the [WeMakeDevs Zerops hackathon](https://www.wemakedevs.org/hackathons/zerops).

## Why

Generating YAML is the easy half. What actually breaks a migration is the
mismatch you find out about *after* deploying:

- `mysql:8` has no managed equivalent on Zerops. You get MariaDB, which is not
  the same database.
- `postgres:13` is older than anything Zerops offers. Rounding it up four major
  versions silently is how you lose a weekend.
- `./data:/var/lib/postgresql/data` has nowhere to bind — containers are
  ephemeral and there is no host filesystem.
- A service named `My_Web_App` is an illegal hostname.
- MongoDB is not offered as a managed service at all.

Zeroshift reports all of it up front, with severity, before you spend anything.

## What it emits

| File | Purpose |
| --- | --- |
| `zerops-project-import.yml` | `zcli project project-import` — creates the services |
| `zerops.yaml` | commit to your repo — drives build and run on every push |

Both are validated against the official Zerops JSON Schemas, vendored under
`schemas/` and refreshable with `python scripts/fetch_schemas.py`.

## Mapping confidence

The tool distinguishes two kinds of claim, and so should you when reading its
output:

- **From the schema.** Which services exist and which versions they offer is
  read out of Zerops' own published JSON Schema. That MongoDB is absent is a
  fact, not a guess.
- **Engineering judgement.** That MariaDB is the right stand-in for MySQL, and
  the specific incompatibilities called out, are reasoned substitutions. They
  are labelled as advisory in the UI. Verify them against your own schema and
  queries before cutting over.

## Run locally

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Open http://localhost:8000. No database needed — share links degrade to
in-memory storage when `DB_HOST` is unset.

```bash
python -m pytest tests/ -q
```

## Deployed on Zerops

Zeroshift's own `zerops.yaml` and `zerops-project-import.yml` were generated by
running Zeroshift over its own `docker-compose.yml`. The running site is
deployed from that generated config.

Architecture is two services, both load-bearing:

- `api` — Python 3.12 runtime, public subdomain, serves the UI and translation
- `db` — PostgreSQL 17, private network, persists share links

Connection details reach the app through Zerops env references
(`${db_hostname}`, `${db_password}`) rather than hardcoded credentials.
